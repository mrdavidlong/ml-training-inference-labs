# Bundled and public datasets

Every training lab reads a file small enough to open and read in full. That is
the point: you can verify what the algorithm learned against data you have
personally inspected.

## The bundled data

| File | Used by | Data rows | What it holds |
|---|---|---:|---|
| `data/house_prices.csv` | `ml-lab-linear` | 20 | Features and a numeric label |
| `data/customer_segments.csv` | `ml-lab-kmeans` | 18 | Points with **no** labels |
| `data/lora_tiny_instructions.jsonl` | `ml-lab-lora` | 24 | Instruction/response pairs |
| *(none)* | `ml-lab-q-learning` | — | Experience generated by acting |

Each lab prints the count it loaded, so you can check the file was read as you
expect: `rows: 20 (train=16, test=4)`, `points: 18`, `examples: 24`.

That last row is the interesting one. Reinforcement learning has no dataset
file at all — the agent creates its own training data by interacting with an
environment. See [docs/11](11-reinforcement-learning.md).

### house_prices.csv — supervised

```text
square_feet,bedrooms,age_years,price_thousands
850,1,28,315
920,2,35,330
1050,2,18,382
...
2700,5,6,895
```

Three **features** and one **label** per row. The label is what makes this
supervised: every example carries its own correct answer. The relationship is
deliberately near-linear — price rises with size, falls with age — so a working
implementation should find it.

```bash
head -5 data/house_prices.csv
uv run ml-lab-linear
```

### customer_segments.csv — unsupervised

```text
annual_spend,visits_per_month
420,1.0
510,1.5
590,2.0
640,1.8
...
```

Two columns, and **no third column saying which group each customer belongs
to**. That absence is what makes clustering unsupervised: the algorithm has to
propose the groups. There is no answer key to score against, which is why
[docs/10](10-kmeans.md) spends its time on how to judge a clustering.

Note the scale mismatch — spending is in the hundreds while visits are in the
single digits. K-means measures distance, so in general that would let spending
dominate entirely. This file was constructed so the groups remain visible
anyway; real data needs standardization first.

### lora_tiny_instructions.jsonl — instruction tuning

JSON Lines: one complete JSON object per line, which streams well and appends
cleanly.

```json
{"instruction":"Expand the acronym LLM.","input":"","output":"LLM means large language model."}
```

| Field | Meaning |
|---|---|
| `instruction` | What the model is asked to do |
| `input` | Optional extra context; empty here |
| `output` | The response to learn |

24 examples cannot teach a model new knowledge. They can nudge its *style* —
which is what [docs/12](12-lora-finetuning.md) demonstrates, and why that guide
insists you compare before and after with greedy decoding.

## What bundled data is and is not

```text
GOOD FOR                              NOT VALID FOR
reading every row yourself            any real decision
verifying an algorithm runs           any performance claim
fast tests, no downloads              measuring model quality
seeing overfitting immediately        generalization evidence
```

All three files are synthetic. With 16 training rows, a model can effectively
memorize; that is a teaching feature, not an oversight.

## Moving to real data

Each lab accepts a `--data` path. Read this before you use it:

**The labs read columns by name, not by position.** Both use `csv.DictReader`
and ask for specific headers:

| Lab | Required column names |
|---|---|
| `ml-lab-linear` | `square_feet`, `bedrooms`, `age_years`, `price_thousands` |
| `ml-lab-kmeans` | `annual_spend`, `visits_per_month` |

So pointing `--data` at an arbitrary CSV raises a `KeyError` on the first row.
You have two honest options: rename your columns to match, or edit the loader
(`load_csv` in `training_labs/linear_regression.py:109`, `load_points` in
`training_labs/kmeans.py:56`) to use your names. Both labs also hardcode the
feature *count* — three for linear regression, two for K-means — so a dataset
with a different shape needs the loader edited, not just renamed.

That is a teaching-code limitation, not a law of nature. Adapting the loader is
a good first exercise.

### California Housing — regression

20,640 rows, eight numeric features. A genuine step up from 21 rows:

```bash
uv run --with scikit-learn python - <<'PY'
from sklearn.datasets import fetch_california_housing
data = fetch_california_housing(as_frame=True)
frame = data.frame
frame.to_csv("data/california_housing.csv", index=False)
print(frame.shape)
print(frame.head())
PY
```

`uv run --with` installs scikit-learn for that one command without adding it to
the project.

California Housing has eight features named nothing like the house-price file's
three, so this is the case that needs `load_csv` adapted rather than renamed —
see the note above. Once it runs, expect a much larger gap between training and
test error than the bundled file shows. That gap is the honest signal 20 rows
cannot give you.

Documentation:
https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_california_housing.html

### Iris — clustering

150 flower measurements, four features, three true species:

```bash
uv run --with scikit-learn python - <<'PY'
from sklearn.datasets import load_iris
data = load_iris(as_frame=True)
data.frame.to_csv("data/iris.csv", index=False)
print(data.frame.shape)
print(data.frame.head())
PY
```

Iris is an excellent K-means exercise precisely *because* the answer is known.
**Do not give the species column to K-means during fitting** — drop it, cluster
on the measurements, then compare the clusters against the species afterwards.
Running `--clusters 2`, `3`, `4`, `5` should see the silhouette score peak at 3,
which is a genuine test of whether that metric can recover a known answer.

Iris has four features, so `load_points` needs widening from two dimensions
first. `squared_distance` already accepts tuples of any length, so the change is
smaller than it looks.

Documentation:
https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_iris.html

### Alpaca-cleaned — instruction tuning

The LoRA lab can stream rows straight from Hugging Face, no download step:

```bash
uv sync --extra lora
uv run ml-lab-lora \
  --hf-dataset yahma/alpaca-cleaned \
  --max-examples 200 \
  --steps 100
```

`--max-examples` is what keeps this feasible on a laptop. Confirm your
arguments before any download starts:

```bash
uv run ml-lab-lora --hf-dataset yahma/alpaca-cleaned --max-examples 200 --dry-run
```

Its fields already match the bundled file's `instruction`/`input`/`output`
shape, which is why no conversion is needed.

Dataset page: https://huggingface.co/datasets/yahma/alpaca-cleaned

## Bringing your own file

| Lab | Format | Works via `--data` alone? |
|---|---|---|
| `ml-lab-linear` | CSV with header | Only if columns are named and shaped exactly as above |
| `ml-lab-kmeans` | CSV with header | Only if columns are named and shaped exactly as above |
| `ml-lab-lora` | JSONL | Yes — `instruction`, `input`, `output` keys |

The LoRA lab is the flexible one: any JSONL with those three keys works
unchanged, which is why the Alpaca example above needs no conversion.

Start small either way. Verify on 20 rows of your own data that the output is
sensible before scaling up — a bug at 20 rows is findable, the same bug at
20,000 is not.

## Data checklist

Before training on any public dataset:

**Legal and ethical**
- License and permitted uses — including whether commercial use is allowed.
- Source and collection method. Was consent obtained?
- Personal or sensitive information. Can individuals be re-identified?

**Quality**
- Duplicates, near-duplicates, and malformed rows.
- Missing values, and how you will handle them.
- Extreme values — genuine outliers or data-entry errors?

**Validity**
- Class and demographic imbalance.
- **Contamination**: does your evaluation data overlap the training data?
  This is the single most common way to produce impressively wrong results.
- Does the data represent the environment the model will actually run in?

**Reproducibility**
- Record the exact revision, version, or checksum. A dataset with the same name
  can change underneath you, and then your earlier numbers cannot be explained.

```bash
shasum -a 256 data/california_housing.csv >> RESULTS.md
```
